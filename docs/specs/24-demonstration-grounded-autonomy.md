# Компонент 24: Обучаемая автономность на демонстрациях

> **Уточнение ADR-0110:** direct similar grant после явного Tier-2
> подтверждения не проходит пороги этого компонента: это уже выданное
> оператором scoped-разрешение. Inferred autonomy ниже действует только в
> `auto`; `plan` использует direct grant лишь для exact approved plan step, а
> `confirm` игнорирует оба механизма.

**Статус:** **LIVE** (2026-08-15, ADR-0103). Production composition создаёт
журнал доказательств и реестр выученных грантов, передаёт порт `learnedAutonomy`
в HookGate, наблюдает ответы оператора через порт `observeApproval`, предлагает
дозревший процесс карточкой тира 3 и гасит автономию каскадом забывания при
архивации проекта или сессии. Выученный грант заглушает
только tier-2 `ask` и только в режиме «без спроса»: в «с подтверждением» и
«сначала план» оператор явно просил спрашивать. Пороги §5 нормативные —
первая автономия возможна не раньше седьмого дня регулярной работы.
**Связанные ADR:** ADR-0061, ADR-0011, ADR-0016, ADR-0017, ADR-0029,
ADR-0047, ADR-0093, ADR-0101, ADR-0103, ADR-0104
**Зависит от:** Safety (05), Memory (03), Nightly (10), Observability (12),
Projects/Sessions (17)

## 1. Назначение

Агент, который повторил один и тот же рабочий процесс правильно N раз под
присмотром, перестаёт спрашивать разрешение на этот процесс — и только на него.
Компонент превращает наблюдаемые демонстрации в **scoped autonomy grants**:
версионируемые, инспектируемые, отзывные разрешения уровня
«проект × инструмент × ресурс», выданные оператором на основании собранных
кодом доказательств.

Разделение по конституции harness:

- **Код (100 %):** сбор доказательств, подсчёт порогов, shadow-оценка,
  оформление гранта, демоушен, отзыв, каскадное забывание. Ни один из этих
  шагов не выполняется моделью и не может быть запрошен из untrusted-контекста.
- **Модель (~70 %):** может *предложить* кандидата («я делал это уже пять раз —
  предложи оператору автономию»), может исполнять рабочий процесс. Предложение
  ничего не меняет: без порогов и подтверждения оно остаётся текстом.

Что этот компонент **не** меняет: тиры риска ADR-0011 остаются
детерминированными. Tier 3 и HARD_DENY не обучаемы — никакое количество
успешных демонстраций не делает деплой или удаление автоматическим.

## 2. Ответственность

**Владеет:**

- Durable evidence store — журнал демонстраций с provenance.
- Каталог кандидатов на автономию и их жизненный цикл.
- Shadow-оценка: сравнение того, что агент *сделал бы*, с тем, что подтвердил
  оператор, без исполнения.
- Карточка promotion/demotion и оформление scoped autonomy grant.
- Каскадное забывание доказательств и грантов.

**Не делает (граница — владелец):**

- Не классифицирует тиры и не исполняет verdict — Safety (05).
- Не хранит содержимое диалога — только ссылки на журнал сессии (23) и
  VerificationTrace (12).
- Не создаёт и не редактирует skills — Skills (06); выученная процедура может
  ссылаться на skill, но его staged-создание идёт по ADR-0015.
- Не выполняет ночную генерацию/суд — Nightly (10); ночной pass лишь поставляет
  кандидатов в этот компонент.

## 3. Интерфейсы

```ts
// иллюстративно, не обязывающе

/** Одна наблюдённая демонстрация. Пишется кодом после завершения хода. */
export interface DemonstrationRecord {
  id: string
  /** Ключ рабочего процесса: детерминированная проекция вызовов, не текст. */
  workflowKey: WorkflowKey
  binding: { operatorId: string; projectId: string; sessionId: string }
  /** Ссылки, не содержимое: журнал сессии + VerificationTrace. */
  evidence: { transcriptRef: string; traceRef?: string }
  outcome: 'confirmed' | 'corrected' | 'rejected' | 'failed-postcondition'
  /** Только operator-provenance ход порождает запись. */
  provenance: 'operator'
  at: string // ISO
}

/** Кандидат, который код вывел из записей. Модель его не создаёт. */
export interface AutonomyCandidate {
  workflowKey: WorkflowKey
  scope: { projectId: string; tool: string; resourcePattern: string }
  tier: 1 | 2                    // tier 3 непредставим по типу
  stats: { confirmed: number; distinctSessions: number; corrected: number }
  shadow: { evaluated: number; matched: number }
  state: 'observing' | 'shadow' | 'offered' | 'granted' | 'demoted' | 'revoked'
}

/** Грант — расширение v3-грантов ADR-0093, а не параллельный механизм. */
export interface LearnedAutonomyGrant {
  candidateRef: string
  version: number
  rollbackRef: string | null     // прежняя версия или null
  issuedBy: 'operator'           // единственное допустимое значение
  proof: ApprovalProof           // step-up обязателен (ADR-0029)
  expiresAt: string              // TTL обязателен; бессрочных нет
}

export interface AutonomyRuntime {
  /** Вызывается кодом после каждого завершённого хода. */
  observe(record: DemonstrationRecord): void
  /** Кандидаты, дозревшие до порога — для карточки оператору. */
  ripeCandidates(): AutonomyCandidate[]
  /** Оформление гранта по подтверждению; вне подтверждения не существует. */
  grant(candidate: AutonomyCandidate, proof: ApprovalProof): LearnedAutonomyGrant
  /** Демоушен: код по событию, оператор по кнопке. Всегда успешен. */
  demote(workflowKey: WorkflowKey, why: DemotionReason): void
  /** Каскадное забывание: проект/факт/сессия исчезли — доказательства тоже. */
  forget(selector: ForgetSelector): { records: number; grants: number }
}
```

Ошибки — всегда значения, не исключения сквозь loop: повреждённый store даёт
`ripeCandidates() → []` и запись в журнал; `grant()` без валидного step-up proof
отвергается детерминированно.

## 4. Структуры данных

- **Evidence store** — append-only JSONL в каталоге состояния владельца (0700);
  проекция строится в памяти при открытии и пересобирается из файла. SQLite-
  проекция добавляется, когда объём этого потребует, — авторитет в любом случае
  JSONL. Записи неизменяемы; исправление — новая запись со ссылкой, как в
  памяти (ADR-0074). Единственное исключение из append-only — каскад `forget`:
  приватность сильнее append-only, файл переписывается без забытых записей.
  Повреждённый файл уходит в карантин (`.corrupt-<ts>`) решением оператора, не
  автоматически; содержимое доказательств не удаляется даже сломанным.
- **WorkflowKey** — детерминированный хэш нормализованной последовательности
  (инструмент, класс аргументов, ресурсная маска). Не содержит свободного
  текста: два «одинаковых» процесса совпадают по ключу или это разные процессы.
- **Гранты** — отдельное durable состояние `LearnedGrantStateV1` рядом с v3-store
  (ADR-0093): у выученного гранта есть версия, `rollbackRef`, TTL и потраченные
  карточки, которых схема v3 не знает, а расширять её ради dormant-среза значило
  бы менять формат живых грантов. Экран «Гранты» читает оба источника и
  показывает один список — различие в хранении, не в интерфейсе.
- **Одна живая версия на процесс.** Новый грант отзывает прежний с причиной
  `superseded`: две действующие версии одного процесса — это два ответа на
  вопрос «что разрешено», а ответ должен быть один.
- **Proof-протокол** зеркалит agent-card lifecycle (ADR-0069): один формат
  доказательств для всех операций, расширяющих полномочия, дешевле в аудите,
  чем три похожих. `cardId` тратится навсегда и переживает рестарт.

## 5. Поведение

```
observe ──► candidate (пороги ниже) ──► shadow ──► offered ──► granted
   ▲              │                        │           │          │
   └── forget ◄───┴── corrected/failed ────┴───────────┴─ demote ◄┘
```

### Пороги (нормативные значения v1)

Все пороги — константы кода. Оператор может ужесточить их в конфигурации;
ослабить ниже нормативных нельзя.

| Порог | Значение v1 | Зачем |
|---|---|---|
| Демонстраций для кандидата | ≥ 5 подтверждённых | одно совпадение — случайность |
| Различных сессий | ≥ 3 | пять подтверждений подряд в одной сессии — это одна привычка одного вечера |
| Календарное окно | ≥ 7 дней между первой и последней | процесс, а не всплеск |
| Исправлений среди последних 5 | 0 | свежая правка обнуляет зрелость |
| Shadow-совпадений | ≥ 3 из 3 последних | агент предсказал ровно то, что оператор подтвердил |
| TTL гранта | 90 дней, продление — новой карточкой | автономия не бессрочна |
| Демоушен | 1 исправление или 1 проваленный postcondition | доверие теряется быстрее, чем набирается |

### Shadow-оценка

Между `candidate` и `offered` компонент не меняет поведение: карточки
показываются как раньше. Код лишь записывает, что *предложил бы* автономный
путь, и сверяет с фактическим решением оператора. Расхождение обнуляет счётчик
shadow. Оценка — сравнение нормализованных вызовов, не модельный суд.

### Promotion

Карточка promotion — **step-up** (ADR-0029): расширение полномочий — это
операция того же класса, что деньги и постоянная память. На карточке: рабочий
процесс словами, точный scope, статистика доказательств со ссылками, TTL.
Кнопки: выдать / показать доказательства / отклонить (отклонённый кандидат
замораживается на 30 дней).

### Enforcement

Выученный грант заглушает **только** tier-2 `ask` и только там, где carte
blanche оператора действительно распространяется. HookGate спрашивает порт
`learnedAutonomy` строго после всех deny-проверок и лишь при выполнении всех
условий сразу:

- вердикт `ask` с `tier === 2` — Tier 3 и HARD_DENY идут своей дорогой всегда;
- ход не narrowed и provenance не `untrusted` — доказательства собирались о
  работе оператора, а не о содержимом, приехавшем снаружи;
- порт вернул ровно `true`; бросок или любое другое значение означают «нет» —
  недоступное хранилище грантов возвращает поведение к карточкам.

Отсутствие порта в композиции означает, что выученной автономии нет вовсе.

### Demotion и отзыв

- Исправление оператора или проваленный postcondition → автоматический демоушен
  в `shadow` + уведомление одной строкой. Грант отзывается немедленно.
- Кнопка на экране «Гранты» отзывает выученный грант так же, как ручной.
- `rollbackRef` позволяет вернуть прежнюю версию гранта той же карточкой
  step-up — откат тоже расширение полномочий относительно текущего состояния.

### Privacy и забывание

- Evidence store хранит **ссылки** на журнал сессии, не содержимое. Удаление
  сессии или проекта каскадно удаляет записи (`forget`), а гранты, чьи
  доказательства опустились ниже порога, демоутятся автоматически.
- Забывание факта в памяти (03) с `topic`, на который ссылались демонстрации,
  вызывает тот же каскад.
- Экспорт/бэкап evidence store подчиняется тем же правилам, что memory: не
  коммитится, не покидает машину без явного согласия.

## 6. Зависимости

- Внутренние: Safety (verdict + grant store), Memory (каскад забывания),
  Nightly (поставка кандидатов ночным судом ADR-0016), Observability
  (VerificationTrace как postcondition), журнал сессии (23) как носитель
  ссылок.
- Внешние: нет. Никаких новых сервисов и моделей; shadow-оценка — чистый код.

## 7. Отказы и деградация

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| Evidence store повреждён | checksum/parse при чтении | fail-closed: кандидаты пусты, гранты **не** отзываются, но и не продлеваются | карантин файла, пересбор проекции из JSONL |
| Grant store недоступен | ошибка чтения v3 store | как сегодня без грантов: всё через карточки | штатный путь v3 |
| Рестарт посреди shadow | нет специальной обработки | счётчики в durable store; незаписанная последняя оценка теряется | добирается следующими ходами |
| Часы ушли назад | `at` новой записи < последней | запись принимается, календарное окно считается по max(at) | нет действий |
| Каскад forget упал на середине | журнал каскада | fail-closed: грант отозван первым шагом, записи дочищаются повторным запуском | идемпотентный повтор |

Порядок в каскаде нормативен: **сначала отзыв гранта, потом чистка записей** —
осиротевший грант опаснее осиротевшей записи.

## 8. Безопасность и модель угроз

| Угроза | Детерминированная защита |
|---|---|
| Untrusted-контекст фабрикует демонстрации | `observe()` вызывается кодом после хода с `provenance: 'operator'`; спан из письма/страницы не порождает запись (ADR-0027/0029) |
| Модель само-повышается | `grant()` требует ApprovalProof со step-up; модель не имеет инструмента записи в evidence/grant store |
| Отравление медленным дрейфом (5 безобидных подтверждений → широкий scope) | scope гранта — точный `projectId × tool × resourcePattern` из фактических демонстраций; расширение scope = новый кандидат с нуля |
| Обучение Tier-3 | `tier: 1 | 2` в типе кандидата; классификация тира — Safety, не этот компонент |
| Реплей старой карточки promotion | proof одноразовый и привязан к хэшу кандидата и версии (как v3-гранты) |
| Забытое не забыто | каскад `forget` тестируется adversarial-кейсом: после удаления проекта grep по evidence store не находит его id |

## 9. Критерии приёмки

1. **AC-24-1** — Запись демонстрации появляется только после завершённого хода
   с operator-provenance; ход с untrusted-спаном записи не порождает.
2. **AC-24-2** — Кандидат созревает строго по порогам §5: 4 подтверждения, или
   5 в одной сессии, или окно < 7 дней — `ripeCandidates()` пуст.
3. **AC-24-3** — Исправление оператора обнуляет зрелость: кандидат с 5
   подтверждениями и 1 свежим исправлением не предлагается.
4. **AC-24-4** — Shadow-расхождение обнуляет shadow-счётчик; кандидат
   предлагается только после 3 совпадений подряд.
5. **AC-24-5** — `grant()` без step-up proof отвергается; proof одноразов;
   повтор той же карточки не создаёт второй грант.
6. **AC-24-6** — Выданный грант точно ограничен scope: тот же процесс в другом
   проекте или с другим ресурсом идёт через карточку.
7. **AC-24-7** — Tier-3 вызов внутри выученного процесса показывает красную
   карточку независимо от гранта; HARD_DENY остаётся отказом; narrowed-ход и
   `untrusted`-provenance грантом не покрываются; бросок порта равен «нет».
8. **AC-24-8** — Одно исправление или один проваленный postcondition отзывает
   грант и переводит кандидата в `shadow`; оператор видит одну строку.
9. **AC-24-9** — Грант с истёкшим TTL не действует; продление — только новой
   step-up карточкой.
10. **AC-24-10** — `forget(project)` удаляет записи проекта и отзывает гранты,
    чьи доказательства опустились ниже порога; повторный вызов идемпотентен;
    после каскада id проекта не находится в evidence store. Живая композиция
    запускает каскад событиями `project.archived` и `session.archived` сервиса
    проектов: разрешение не переживает проект, ради которого набиралось.
11. **AC-24-11** — Повреждённый evidence store даёт пустых кандидатов и запись
    в журнал; существующие гранты продолжают действовать до TTL.
12. **AC-24-12** — Рестарт между `offered` и тапом не теряет и не дублирует
    карточку: кандидат остаётся `offered`, старая карточка мертва (одноразовый
    nonce), новая выпускается по запросу.
13. **AC-24-13** — Экран «Гранты» показывает выученные гранты рядом с ручными,
    с версией, сроком и числом демонстраций; отзыв поштучный, с того же экрана,
    отдельной кнопкой на процесс. Callback отзыва принимает только точную форму
    ключа процесса. Название процесса экранируется. Без выученных грантов экран
    остаётся прежним.
14. **AC-24-14** — Демонстрация записывается только после хода, дошедшего до
    конца: подтверждение в ходе, который упал или был прерван, доказательством
    не становится. Наблюдатель не может изменить решение по вызову — его бросок
    не превращает `allow` в `deny` и наоборот.
15. **AC-24-15** — Вызов, пропущенный выученным грантом, демонстрацией не
    становится: иначе автономия продлевала бы собственные доказательства и
    отозвать её было бы нечем.
16. **AC-24-16** — Карточка промоушена подтверждается тапом оператора
    (ADR-0104): второй фактор действует только там, где установка передала
    шлюзу проверяющего, и встроенного запасного, принимающего любую строку
    «correct…», у шлюза нет. `proof.stepUpVerified` карточка несёт в обоих
    случаях, и промоушен без него по-прежнему отказывает.
17. **AC-24-17** — Ключ рабочего процесса строится той же проекцией вызова, что
    и «похожее действие» из ADR-0093: то, что код считает одинаковым при
    подтверждении, он обязан считать одинаковым при обучении. Составная
    shell-команда, делегирование, путь за пределы проекта и не-https ссылка
    процессом не становятся.

## 10. Открытые вопросы

- **Гранулярность WorkflowKey.** Слишком узкий ключ никогда не соберёт 5
  демонстраций; слишком широкий склеит разные процессы. v1 фиксирует
  нормализацию (инструмент + класс аргументов + ресурсная маска), калибровка —
  по реальным данным после LIVE evidence store.
- **Ночная поставка кандидатов.** Судья ADR-0016 может предлагать кандидатов из
  ночного разбора; v1 ограничивается наблюдением живых ходов, чтобы не смешать
  два источника доказательств до приёмки первого.
- **Публичный экспорт выученного.** Перенос выученной процедуры на другую
  машину оператора — отдельный ADR (перенос доказательств ≠ перенос гранта).
