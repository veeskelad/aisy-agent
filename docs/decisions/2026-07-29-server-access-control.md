# ADR-0086: Управление доступом к серверу — только заранее описанные операции, всегда с подтверждением и на срок

**Статус:** Принято
**Дата:** 2026-07-29
**Теги:** operations, safety, approvals

## Контекст

Оператор управляет установкой с телефона. Когда что-то ломается, ему нужен
доступ к серверу: открыть SSH, добавить ключ с нового устройства, поднять
туннель редактора, а в тяжёлом случае — аварийную консоль.

Сейчас всего этого нет: единственный путь — уже иметь доступ, то есть ровно то,
чего нет в момент, когда он понадобился.

Соблазн решить это «агент выполнит нужную команду» опасен вдвойне. Во-первых,
такие операции необратимы наружу: открытый порт видит весь интернет, добавленный
ключ даёт доступ навсегда. Во-вторых, вход в диалог — недоверенный: сообщение,
пересланное из канала, не должно даже теоретически приводить к добавлению чужого
ключа.

## Решение

1. **Агент не сочиняет команды.** Выполняются только операции, заранее описанные
   оператором в конфигурации установки: открыть порт, закрыть порт, добавить
   ключ, снять ключ, поднять туннель. Нет описания — нет операции, и отказ
   говорит именно это.

2. **Каждая операция проходит подтверждение и попадает в аудит.** Это tier-2
   действие: карточка, решение оператора, запись с тем, что именно было
   выполнено и когда.

3. **Открытый доступ живёт по таймеру.** У открытия порта и туннеля есть срок;
   по его истечении рантайм закрывает их сам. Доступ, который забыли закрыть, —
   основной способ, которым временная мера становится постоянной дырой.

4. **Публичный ключ проверяется как данные.** Принимаются только известные типы
   и корректная база-64. Текст, похожий на приватный ключ, отвергается сразу и
   не попадает ни в аудит, ни в сообщение об ошибке: приватный ключ, присланный
   по ошибке, не должен быть ещё и записан.

5. **В аудит идёт отпечаток, а не ключ.** Отпечатка достаточно, чтобы опознать
   устройство, и он не превращает журнал в набор рабочих ключей.

6. **Инициатором может быть только оператор.** Операция, запрошенная из
   недоверенного контекста, отвергается до подтверждения — карточка на такое
   даже не выпускается.

## Последствия

- Оператор чинит установку с телефона, не имея заранее доступа к ней.
- Набор возможных операций конечен и виден в конфигурации, а не выводится из
  того, что агент сумел придумать.
- Открытый доступ закрывается сам, даже если про него забыли.
- Установка без конфигурации доступа отвечает отказом. Это верно: молчаливый
  дефолт здесь означал бы выполнение системных команд, о которых никто не
  просил.
- Аудит показывает, кто и когда открывал доступ, но не даёт им воспользоваться.

## Альтернативы

- **Дать агенту `bash` с sudo.** Отвергнуто: недоверенный вход и необратимые
  наружу действия в одном контуре — это ровно тот класс проблем, ради которого
  существует narrow waist.
- **Постоянно открытый SSH.** Отвергнуто: постоянная дыра ради редкого случая.
- **Доступ без срока, закрываемый вручную.** Отвергнуто: «закрою потом» — самый
  надёжный способ оставить порт открытым навсегда.
- **Хранить ключи в аудите целиком.** Отвергнуто: журнал не должен быть связкой
  ключей.
