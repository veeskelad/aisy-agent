# ADR-0090: Подписочный мозг с инструментами Aisy через локальный MCP-мост

**Статус:** Принято
**Дата:** 2026-08-05
**Теги:** providers, tools, safety, subscriptions

## Контекст

Оператор хочет работать на подписке (Claude Pro/Max), а не по API-ключу, и при
этом иметь полноценного агента: файлы, память, команды, навыки. До сих пор оба
пути к подписке давали не то:

- `claude-cli` ([provider-cli.ts](../../packages/core-ts/src/runtime/provider-cli.ts))
  живой, но reply-only: `tools` теряются при сборке провайдера, обратного канала
  нет, tool-calling невозможен архитектурно;
- supervised `claude-code` драйвер разобран до `stream-json`, но заперт
  fail-closed: `CLAUDE_ACTION_TURN_UNSUPPORTED` для всех профилей кроме
  smoke-readonly и `CLAUDE_ISOLATION_FAILED` до любого запуска процесса.

Проверка живого CLI 2.1.220 показала жёсткое ограничение: **`claude -p` не
принимает чужие tool-схемы**. Внешние инструменты доступны ему только через MCP.
Значит выбор всего два: отдать модели её собственные инструменты (путь
референсного ассистента)
или отдать ей инструменты Aisy по MCP.

[ADR-0057](./2026-07-26-aisy-control-plane-supervised-brain-runtimes.md) уже
запретил первый вариант для action-ходов: непрозрачный второй loop обходит
control plane, а Aisy теряет tool-события, подтверждения и наблюдаемый прогресс.
Спека 16 §10 оставила открытым только выбор wire transport для моста.

## Решение

Aisy поднимает **локальный MCP-сервер на время одного вызова модели** и отдаёт
ему свой narrow-waist каталог. CLI получает мозг и ничего больше:

```
-p --output-format stream-json --include-partial-messages
--strict-mcp-config --mcp-config <loopback http + bearer>
--tools '' --allowedTools mcp__aisy__* --permission-mode dontAsk
--setting-sources '' --disable-slash-commands --no-session-persistence
```

- `--tools ''` снимает Bash/Edit/Read из контекста модели — не «запрещает
  вызывать», а физически убирает;
- `--strict-mcp-config` отсекает `.mcp.json` и `~/.claude`, `--setting-sources ''`
  — CLAUDE.md, хуки и плагины хоста;
- каждый вызов возвращается в живую композицию и проходит общий
  `makeCodexCapabilityExecutor`: safety policy, hook gate, гранты, режим
  исполнения и карточка одобрения в Telegram.

**Транспорт — loopback HTTP, а не stdio.** stdio заставил бы CLI породить второй
процесс Aisy, которому понадобились бы собственные блокировки памяти и который
исполнял бы инструменты вне живой композиции. Сервер слушает только `127.0.0.1`
на случайном порту и требует bearer-токен, выпускаемый на каждый вызов.

**Два fail-closed условия.** Ход прекращается, если в init-кадре мост не
`connected` либо уцелел хоть один нативный инструмент. Первое критично: неверный
`--mcp-config` не роняет прогон — сервер молча выбрасывается, и модель ответила
бы вообще без инструментов, что внешне неотличимо от нормального хода.

`--safe-mode` **не используется**: он отключает MCP заодно с хуками (проверено на
2.1.220), то есть гарантированно оставил бы модель без инструментов.

## Последствия

- Подписка становится полноценным мозгом: модель рассуждает, Aisy действует.
  Побочные эффекты, бюджеты, журнал и подтверждения остаются за Aisy.
- Внутренний цикл CLI признаётся допустимым — это отступление от
  [ADR-0005](./2026-06-11-own-agent-loop.md) в части «свой loop», но не в части
  контроля: enforcement стопроцентно наш, потому что исполняем мы.
- Карточка исполнения показывает вызовы моста со временем: провайдер эмитит
  `tool-requested`/`tool-result`, иначе ход выглядел бы молчаливым.
- Протокол привязан к формату `stream-json` конкретной ветки CLI; изменение
  формата ломает разбор, поэтому init-кадр валидируется, а не читается наугад.
- Лимиты подписки общие с интерактивным Claude Code (5-часовое окно). Программное
  использование `claude -p` сейчас идёт из пула подписки, но Anthropic уже
  анонсировала (14.05.2026) и приостановила (15.06.2026) вынос его в отдельный
  кредит — экономика может измениться.
- Модель читает описания инструментов и их результаты, поэтому инъекция из
  tool-result уводит именно её. Входной классификатор результатов не сделан.
- Codex-подписка подключена отдельным version-pinned `codex app-server`
  адаптером. Для каждого хода он создаёт новый loopback MCP bridge, передаёт
  только allowlist Aisy tools, связывает вызовы с exact thread/turn и выключает
  нативные action surfaces в thread config. Device auth и runtime используют
  один private `CODEX_HOME`; сквозной offline-тест доказывает путь
  app-server → MCP → общий executor без внешней сети.

## Альтернативы

- **Родные инструменты CLI (путь референсного ассистента).** Отклонено: Aisy не видит tool-события
  и время, подтверждения превращаются в поведение модели, а не в замок.
- **CLI как текстовый провайдер + свой tool-loop.** Отклонено: структурированных
  tool-calls из подписки получить нельзя, только самодельный JSON-протокол без
  валидации, параллельных вызовов и со сбросом контекста на каждом шаге.
- **Снять `CLAUDE_ISOLATION_FAILED` в claude-code-node.** Отложено: требует
  managed-policy/container аттестора. Провайдер использует простой spawn с
  allowlist окружения; аттестор — путь усиления, а не условие работы.
