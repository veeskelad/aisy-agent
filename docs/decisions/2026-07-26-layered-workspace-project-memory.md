# ADR-0063: Layered Workspace and Project Memory

**Status:** Accepted (amended by ADR-0065 and the Component 17 normative design)
**Date:** 2026-07-26
**Tags:** memory, projects, context

## Context

ADR-0060 introduced project ownership for sessions and files, but its first
memory formulation placed the legacy memory inside the default project and
required explicit promotion before any fact became global.

The reference assistant the operator works from is more specific: a shared
personal workspace, isolated project workspaces, and resumable dialogue
sessions. The operator has directed Aisy to treat that observed behaviour as the
product contract for every corresponding capability. The reference material is
private and stays outside this repository; what is recorded here is Aisy's own
requirement, written independently.

Aisy must preserve that useful behaviour while retaining its existing
append-only transcript, frozen-prefix, durable-forgetting, provenance, and
code-enforced path invariants.

## Decision

Use a four-layer memory and context model.

1. **Global DNA and personal memory in the operator workspace.**
   `constitution.md`, `SOUL.md`, `USER.md`, `MISSION.md`, `GOALS.md`,
   `PROJECTS.md`, `PREFERENCES.md`, `LEARNED.md`, `CLAUDE.md`, and
   `SERVICES.md` are available in every project. Human-readable live facts
   are canonical under global `memory/facts/`; `MEMORY.md` is their
   deterministic generated prefix/index, not a direct authored fact sink.
   Global `memory/YYYY-MM-DD.md` contains explicit cross-project-safe text and
   opaque references to project events, never copied project detail. Global
   `knowledge/` remains available through its index and on-demand retrieval.

2. **Project-local work memory.**
   Every project root owns its files, git history, `memory/`,
   `knowledge/`, project tasks, project skills, and active
   `.current-task.md`. Project-local search and writes must include
   `project_id` and may never fall back to another project.

3. **Session context.**
   A session is a resumable topic of dialogue inside one project, independent of
   Telegram chat id. It owns an append-only transcript, tool observations, and
   a compaction view. `/newtask` creates a new session without deleting the
   old one; `/sessions` can resume sessions created through Telegram or a
   connected development interface. Switching projects starts or selects a
   session for the new project and cannot reuse the previous project's live
   context. Switching incompatible brain engines or models starts a fresh
   session while retaining old transcripts.

4. **Current turn.**
   The operator input, retrieved evidence, and tool results form the mutable
   tail after the stable memory prefix.

At session start Aisy freezes the stable global DNA prefix as required by
ADR-0007. Writes are durable immediately and searchable in the same session,
but the always-loaded prefix refreshes at the next session. Project indexes,
daily notes, the current task, and knowledge articles are loaded lazily and do
not invalidate the stable prefix.

Memory routing is deterministic:

- durable fact about the operator, preference, contact, mission, or active
  project summary → canonical global `memory/facts/<fact-id>.md`, with
  deterministic projections into the appropriate generated/read surfaces;
  `constitution.md` remains authenticated operator-only;
- reusable lesson or observed working pattern → `LEARNED.md`, with evidence
  and the scoped-autonomy rules of ADR-0061;
- cross-project-safe fact or day summary → global daily journal; completed
  project work, decisions, topic changes and context flushes → only the
  project's `memory/`, while the global journal may retain an opaque
  `projectId + note hash + timestamp` reference;
- multi-step active work → active project's `.current-task.md`;
- long research, article, template, configuration, or reusable decision →
  active project's `knowledge/`, or global `knowledge/` only when the
  operator explicitly makes it cross-project;
- durable task tracking → the active project's task store.

`MEMORY.md` is regenerated byte-deterministically from canonical live facts,
has a hard 10 KiB limit, and emits a consolidation warning at 8 KiB. Duplicate
candidates are checked before commit through the scoped memory choke point. The daily journal and
knowledge corpora are unbounded by prompt size because only today's note,
catalogues, and retrieved excerpts enter context. Keyword search is always available through FTS5/BM25. ADR-0065 makes semantic
and deterministic hybrid retrieval first-class derived capabilities, backed by
local scope-isolated vector indexes; they visibly fall back to keyword search
when the embedding provider is unavailable.

Code, not the model, resolves every destination relative to the selected
workspace/project, validates ownership and symlink confinement, records
provenance, and rejects ambiguous, absolute, traversing, or colliding paths.
The model may choose a semantic category and propose a filename; it cannot
choose an unchecked physical path.

This decision partially supersedes only the memory-topology and legacy-memory
paragraph of ADR-0060. ADR-0060 remains authoritative for project, session, and
file ownership.

## Consequences

- **Positive:** Aisy keeps one personal identity across projects while project
  notes, knowledge, tasks, skills, and active work remain isolated.
- **Positive:** file placement is explainable, deterministic, inspectable, and
  recoverable after a session or process restart.
- **Positive:** Telegram and development interfaces can resume the same durable
  sessions over the same files and memory.
- **Neutral:** a separate Workspace is created at the configured global root;
  the legacy v1 default remains a Project because it may be the current repo.
  Legacy global-memory material is copied losslessly and classified with
  provenance rather than being silently promoted or discarded.
- **Negative:** one logical context now spans a global workspace, a project
  root, a session log, and derived indexes, requiring explicit routing and
  cross-layer tests.
- **Negative:** facts written during a session do not alter the frozen stable
  prefix until the next session, although immediate search still finds them.

## Alternatives considered

**Put all memory inside each project.** Rejected because it contradicts the
required behaviour: identity, personal facts, goals, preferences, learned
patterns, and the global journal must survive project switches.

**Use one global memory and tag project facts.** Rejected because tags do not
provide physical file, git, skill, task, or retrieval isolation.

**Let the model invent destinations and paths.** Rejected because it produces
inconsistent layouts and cannot enforce project ownership or traversal
protection.

**Store only vector memory.** Rejected by ADR-0006: canonical memory must remain
human-readable and auditable files; vectors are first-class but disposable
derived indexes, never the source of truth.
