# ADR-0074: Защищённая scoped-память как единственная живая память

**Статус:** Принято
**Дата:** 2026-07-29
**Теги:** memory, architecture, migration

## Контекст

В live-композиции память собирается legacy-хранилищем `Memory` (`memory/index.ts`):
один SQLite и один каталог файлов, без привязки к оператору, проекту и сессии.
Параллельно построена защищённая scoped-память (ADR-0063): protected ledger,
файловый store с проверкой установленных байт, семантический индекс, барьер
scope и recovery gate. Она полностью реализована и покрыта тестами, но к модели
не подключена.

Прямая замена невозможна: контракты расходятся не только по именам.

- `ScopedMemoryRouter` имеет пять методов (`searchAutomatic`, `commitGlobal`,
  `commitProject`, `forgetGlobal`, `forgetProject`), и **каждый требует
  `TurnContextLease`**; scope выводится из лизы, а не передаётся аргументом.
- У legacy-поверхности одиннадцать методов. Три из них в scoped-модели не имеют
  аналога вообще: `readFrozenSnapshot` (стабильный префикс KV-кэша),
  `serializeMemoryIndex` (byte-stable `MEMORY.md`) и `load` (трёхшаговая ленивая
  загрузка). Ещё две — `reindex`/`rebuildFromFiles` — в scoped-модели заменены
  восстановлением незавершённых операций, а не перестройкой индекса из файлов.
- Шесть вызовов работают вообще без лизы: cold-start `rebuildFromFiles`,
  nightly (`listLive`, `reindex`, `forget`, `commit`), инструмент `remember` и
  onboarding (`integrityCheck`).

Пока это не решено, «сразу v2» для памяти недостижимо: любая частичная замена
оставит два источника истины.

## Решение

Живая память — **только защищённая scoped-память**. Legacy `Memory` из
live-композиции убирается целиком, а расходящиеся операции переносятся туда, где
им место.

1. **Префикс — не память.** `readFrozenSnapshot` перестаёт быть операцией
   памяти. Стабильный префикс собирается отдельным компонентом из файлового слоя
   (DNA-файлы плюс сгенерированная проекция), а не из ledger. Память отдаёт ему
   факты, но не владеет форматом префикса.
2. **`MEMORY.md` — детерминированная проекция.** `serializeMemoryIndex`
   реализуется поверх `store.listLiveFacts()` защищённого ledger: тот же
   byte-stable порядок, тот же контракт хэша. Это проекция, а не источник.
3. **Ленивая загрузка — через verified-файлы.** `load` реализуется поверх
   `files.verifyInstalled({sourcePath, contentHash, sizeBytes})`: scoped-хит уже
   несёт путь и хэш, поэтому шаг загрузки читает проверенные байты и не может
   вернуть содержимое, не совпадающее с ledger.
4. **Восстановление вместо переиндексации.** `rebuildFromFiles` и `reindex`
   заменяются `recovery.assertScopeRecovered`/`recoverScope`. Индекс не
   перестраивается «из файлов»: файлы больше не являются авторитетом, им является
   ledger, а деривативы восстанавливаются из него.
5. **Лиза обязательна везде.** Ни один путь не получает памяти без лизы:
   - фоновые задачи (nightly, триггеры, цели) берут собственную project-bound
     лизу своей привязки;
   - обслуживающие операции без диалога (cold start, onboarding, doctor) берут
     отдельную короткоживущую maintenance-лизу того же оператора и Workspace;
   - инструмент `remember` работает под лизой текущего turn.
   Отсутствие лизы — отказ, а не молчаливый общий доступ.
6. **Один источник истины.** После перехода legacy `Memory` не собирается в
   `aisy run` вовсе. Модуль остаётся в кодовой базе только как источник данных
   для миграции существующих установок.

## Последствия

- **Положительные:** у каждой записи памяти появляется оператор, проект и
  сессия; удаление и forget проходят через проверяемый ledger; поиск больше не
  смешивает контексты; исчезает второй источник истины.
- **Нейтральные:** появляется maintenance-лиза как явное понятие; `MEMORY.md` и
  префикс переезжают из памяти в проекцию и сборку контекста.
- **Отрицательные:** каждый вызов памяти становится дороже на резервирование
  операции в лизе; фоновые пути обязаны знать свою привязку, иначе просто не
  работают.

## Рассмотренные альтернативы

**Оставить legacy-память как fallback.** Самый дешёвый путь, но именно он
создаёт два источника истины: forget в одном хранилище не действует на другое.

**Добавить в `ScopedMemoryRouter` недостающие методы.** Расширяет узкий контракт
операциями, которые не имеют смысла в scoped-модели (`rebuildFromFiles` вернул
бы файлам авторитет, отобранный у них ledger).

**Разрешить безлизовые вызовы для фоновых путей.** Убирает обязанность знать
привязку, но возвращает ровно ту неявную общую память, ради ухода от которой
scoped-модель и вводилась.
